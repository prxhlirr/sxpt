# 发布中心与讲解/学习交互优化设计

## 目标

在不改变发布业务规则和接口调用方式的前提下，完成三项前端体验优化：

1. 将发布中心改为“状态总览 + 横向发布流程”的控制台样式。
2. 教师讲解与学生学习进入教学点后，自动在业务界面侧边显示该教学点的附件层叠框，并允许整组拖动。
3. 讲解/学习目录不再一次展示全部节点，只展开当前选择教学点下的节点。

教师讲解和学生学习继续共用同一个 `LessonPlaybackPlayer`，确保两端展示、附件行为和目录行为一致。

## 范围

### 包含

- `PublishCenterView` 的信息层级、布局、状态样式和响应式调整。
- `LessonPlaybackPlayer` 的教学点树形目录、教学点选择和节点索引换算。
- `AttachmentPreviewLayer` 的教学点附件组、层叠停靠、整组拖动和单附件完整预览。
- 与上述行为直接相关的单元测试、类型检查、生产构建和页面验证。

### 不包含

- 不修改学习、练习发布接口和发布条件。
- 不修改教案、教学点或附件的数据结构及后端接口。
- 不改变学生练习与考试界面。
- 节点附件不自动停靠，仍在节点说明中由用户按需点击预览。

## 现有结构与设计选择

教师讲解页面 `RecordingPreviewView` 和学生学习页面 `StudentTaskRunnerView` 已共同使用 `LessonPlaybackPlayer`。播放器内部又统一使用 `AttachmentPreviewLayer` 预览附件，因此在共享组件中增强行为可以同时覆盖两端，避免复制状态和交互。

采用以下组件边界：

- `PublishCenterView` 只负责发布中心视觉层和现有状态的展示，不改变发布方法。
- `LessonPlaybackPlayer` 负责判断当前教学点、生成目录树、处理教学点/节点选择，并把当前教学点附件传入附件层。
- `AttachmentPreviewLayer` 负责显示教学点附件层叠组、维护组位置、打开单个附件以及完整预览与最小化之间的切换。
- `draggableOverlay` 提供视口边界计算和拖动更新；附件组复用该工具，不另写一套拖动算法。

不采用教师端、学生端分别维护附件和目录状态的方案，因为这会重复实现并再次产生两端不一致风险。

## 发布中心

### 信息结构

页面顶部使用教案概览横幅，展示：

- 教案名称与当前发布状态。
- 教学点数量。
- 录制节点数量。
- 教师讲解完成状态。
- 已分配学生数量。
- 已准备练习数据数量。

概览下方使用两步横向流程：

1. 教师讲解。
2. 发布学生学习与练习。

第一步展示讲解完成状态及“开始讲解/重新讲解”入口。第二步分别展示学习任务和练习任务的同步状态，并保留现有发布按钮。

### 行为约束

- 发布按钮继续使用现有 `lectureCompleted`、`publishing` 和 `trainingTasksReady` 条件。
- 发布动作继续调用 `publishLearningAndPracticeRemote`。
- 后端同步失败信息继续由 `syncLabel` 和页面反馈区展示。
- 已发布结果区继续提供查看学生任务入口。
- 教案不存在时继续展示返回教案管理的空状态。
- 视口宽度不足时，两步流程改为纵向排列，指标区按可用宽度换行。

## 教学点与节点目录

### 展示规则

目录由原来的“全部教学点区 + 全部节点区”改为单一教学点树：

- 始终展示所有包含录制节点的教学点。
- 当前教学点默认展开，并在教学点下方显示其节点。
- 其余教学点只显示名称和节点数量，不渲染其节点列表。
- 点击另一个教学点后，该教学点成为唯一展开项，并先展示教学点说明。
- 点击展开教学点内的节点后，直接进入该节点说明和业务快照。

### 索引与进度

播放器现有上一页、下一步和进度仍以全流程扁平步骤数组为准。目录中的教学点节点需要把局部节点位置映射为扁平步骤数组中的全局索引，再触发现有 `selectStep(index)` 事件。

教学点选择继续触发现有 `selectStage(stageId)` 事件，因此教师讲解和学生学习的父页面状态机不需要增加新的事件类型。

目录在 `READY` 和 `COMPLETED` 状态下保持不可跳转；只有 `PLAYING` 状态允许切换教学点或节点，与现有规则一致。

## 教学点附件层叠组

### 自动展示

播放器进入教学点说明或该教学点任一节点时，读取当前教学点的全部附件：

- 每个附件显示为一个独立最小化小框。
- 多个小框采用固定偏移形成层叠效果，同时保留文件名和附件类型标识。
- 附件组默认停靠在业务界面侧边。
- 教学点没有附件时不渲染附件组。

只有教学点附件自动进入层叠组。节点附件继续显示在节点说明的 `AttachmentPanel` 中，由用户点击后进入同一完整预览层。

### 拖动

- 层叠组只有一个共享坐标。
- 用户从任意附件小框的非按钮区域开始拖动时，整组一起移动。
- 拖动范围限制在可视区域内。
- 窗口尺寸变化后重新钳制坐标，保证附件组仍可见。
- 用户未手动拖动时，如果目录打开会遮挡附件组，播放器自动把附件组移到另一侧。
- 用户已经手动拖动后，不再因目录开关强制改变其位置。

### 预览、最小化与关闭

- 点击某个附件小框后打开该附件的完整预览窗口。
- 完整预览沿用 Open File Viewer，继续支持图片、PDF、Office、文本、音视频和格式兜底。
- 点击最小化或按 `Esc` 后关闭完整窗口，恢复教学点附件层叠组原位置。
- 完整预览期间只选择一个活动附件，不改变当前教学点附件集合。
- 关闭某个附件后，该附件在当前教学点本次停留期间隐藏。
- 离开后重新进入该教学点时，恢复显示该教学点全部附件。
- 切换教学点时立即关闭旧附件完整预览，清除旧教学点的临时隐藏状态，并把层叠组替换为新教学点附件。

### 加载失败

附件完整预览加载失败时，保留：

- 附件名称。
- MIME 类型与文件大小。
- 错误说明。
- 下载原文件入口。

加载失败不影响目录切换、教学点切换或讲解/学习进度。

## 响应式与遮挡控制

- 桌面端附件组使用固定最大宽度，并以小幅横向、纵向偏移形成层叠。
- 窄屏下缩短附件框宽度并减小层叠偏移，确保关闭按钮可见。
- 目录继续使用单列抽屉，小屏幕占用可用宽度但不改变教学点树规则。
- 附件组、目录和说明浮窗使用明确的层级关系；完整附件预览位于最上层。
- 业务 iframe/快照继续占据整个播放器视口，新增元素只作为上层浮动控件存在。

## 状态与数据流

1. 父页面把教案、当前全局步骤索引和教学点说明状态传给 `LessonPlaybackPlayer`。
2. 播放器从扁平步骤数组计算当前教学点，并生成只展开当前教学点的目录数据。
3. 当前教学点变化时，播放器向附件层传递新的教学点附件数组和教学点标识。
4. 附件层根据教学点标识重置临时隐藏集合、活动预览附件和默认停靠位置。
5. 用户点击附件小框后，附件层打开单附件完整预览；最小化后返回附件组。
6. 用户选择教学点或节点时，播放器继续向父页面发送现有事件，由父页面更新步骤与说明状态。

## 测试与验收

### 自动化测试

- 发布中心显示教案摘要、两步流程以及学习/练习独立状态。
- 发布按钮继续遵守现有禁用条件，并调用原发布方法。
- 目录只渲染当前教学点的节点。
- 点击教学点触发 `selectStage(stageId)`。
- 点击教学点内节点时正确换算并触发全局 `selectStep(index)`。
- 当前教学点附件自动形成层叠组，节点附件不会自动加入。
- 切换教学点替换附件组并关闭旧预览。
- 拖动任意附件框更新共享组位置，并受到视口边界限制。
- 完整预览最小化后恢复原附件组位置。
- 窗口尺寸变化后附件组仍位于视口内。

### 构建验证

- 运行相关 Vitest 测试。
- 运行前端完整测试集。
- 运行 TypeScript 类型检查。
- 运行 Vite 生产构建。

### 页面验收

- 教师从发布中心进入讲解，检查教学点目录、附件自动停靠、整组拖动和附件预览。
- 使用学生账号进入同一教案的学习任务，确认目录、附件和预览行为与教师讲解一致。
- 切换多个教学点，确认只展示当前教学点节点和附件。
- 在不同窗口尺寸下确认业务界面仍占满播放器，附件组和目录不会永久遮挡关键操作区域。
