# sxpt_web 实训平台前端

一个可独立运行的 Vue 3 + TypeScript + Vite 前端 Demo，在同一项目中提供后台管理、教师端和学生端，并用可替换的 Mock 数据层串联完整业务流程。

## 已实现的业务链

```text
教案编排、录制与备案
  → 教师全屏讲解
  → 发布流程学习与练习
  → 学生看一遍流程并完成练习
  → 考试设置与发布
  → 动态角色分组
  → 按单位生成正式/备用考试数据
  → 学员在全屏业务界面按角色串行办理
  → 系统生成客观分
  → 教师监控、主观评分与批语
  → 学员查看完整结果
```

### 后台管理

- 运营总览：显示五步业务链就绪状态和最近操作。
- 教案列表：搜索、筛选、新建、复制、录制回看、继续编排和发布。
- 教案编排：基础信息、动态业务阶段、录制步骤、分值、完成判定、三种运行模式可见性。
- 教师讲解：业务界面占满视口，讲解步骤、进度和完成动作以浮窗显示；讲解完成后才允许发布学习、练习任务。
- 考试设置：批次、时间、时长、重答次数、评分权重、随机数据和动态提交字段；运行时会校验考试窗口、单次时长和必填提交字段。
- 分组设置：支持任意数量的业务角色组，不写死 A/B；同一学员可承担多个角色，也可由多人串行完成。角色组人数不等时，下游成员会轮转承接上游产生的每一条业务数据。
- 考试数据：按单位配置正式/备用数量，通过 Mock 业务接口生成；支持部分失败、重试、停用、备用转正式、替换和审计记录。
- 发布中心：进行五步就绪检查，通过后生成考试批次和学员任务。
- 版本保护：考试任务发布后冻结教案、考试规则、分组和造数计划；需要调整时复制教案创建新版本，避免追溯改变在考或历史成绩。

### 教师端

- 考试全过程监控：按批次查看学员、角色、阶段、完成率和平台操作轨迹。
- 主观评阅：保留系统客观分，教师补充主观分与批语，并向学员结果页推送。

### 学生端

- 我的任务：按当前演示学员会话查看分配到的角色和业务数据。
- 任务办理：学习、练习和考试统一使用全屏业务界面，阶段与操作引导浮窗显示在上层；流程性操作会同步为后端执行轨迹。
- 提交前重答：在配置次数内为整个协作单元申请一条新的同单位业务数据，旧数据停用但不回滚，相关角色从新数据重新开始。
- 成绩反馈：查看系统客观分、教师主观分、批语和阶段记录。

## 运行

要求 Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

开发服务默认从 `http://localhost:5173` 访问。首次进入后台管理总览，左侧可直接切换后台、教师和学生三个端。

## 后端接口配置

前端使用 Axios 调用后端，运行时配置位于 `public/api-config.js`。部署后可直接修改该文件，无需重新构建：

```js
window.__SXPT_API_CONFIG__ = {
  enabled: true,
  apiBaseUrl: 'http://127.0.0.1:8080/api/v1',
  timeoutMs: 15000,
  bearerToken: '',
  autoDevToken: true,
  tenantId: 'demo-tenant',
  currentUserId: 'demo-teacher',
  currentUsername: 'demo-teacher',
  simulatedOrgId: 'demo-class',
  simulatedStudentId: 'demo-student',
  simulatedStudentName: '模拟学生'
};
```

- 本地 `dev` 后端可开启 `autoDevToken`，前端会在首次业务请求前通过 `/auth/token` 获取测试 Token。
- 正式环境应关闭 `autoDevToken`，使用 `/auth/login` 返回的 Token，或由部署环境配置 `bearerToken`。
- 如需暂时只演示本地数据，把 `enabled` 改为 `false`。
- 后端跨域白名单通过 `sxpt.cors.allowed-origins` 配置，多个地址使用英文逗号分隔。

当前已接入业务平台、采集会话、事件、资源摘要、动作草稿、正式资源、教学点、课程、学习/练习/考试任务、教学步骤、评价规则、学生执行上下文、执行轨迹和自动评分接口。模拟班级会按编码复用或自动创建；用户、角色和正式登录逻辑仍按本阶段要求保留为模拟配置。

## 目录结构

```text
src/
├─ api/              Axios 客户端、接口契约与分模块 API
├─ config/           后端运行时配置读取
├─ components/       通用组件及考试链组件
├─ data/             初始 Mock 业务数据
├─ domain/           领域类型
├─ layouts/          三端统一应用壳
├─ services/         可替换的训练数据仓储
├─ stores/           响应式业务状态与业务动作
└─ views/
   ├─ admin/         后台管理
   ├─ teacher/       教师端
   └─ student/       学生端
```

## 本地状态与后端接口边界

页面不直接读写 `localStorage`，所有业务动作统一经过 `src/stores/trainingStore.ts`。页面编排草稿和当前 Demo 尚无对应表结构的展示字段继续缓存在浏览器；后端已有契约的权威记录通过 `src/services/backendTrainingApi.ts` 写入后端：

- 业务平台创建、更新、启用、停用和列表查询使用后端接口。
- 开始录制会创建 `capture_session`。
- 业务操作会依次上报 `capture_event`、`resource_snapshot` 并创建 `action_draft`。
- 发布教案会沉淀 `connector_resource`、确认动作草稿、创建 `teaching_point` 并结束采集会话。
- 平台模块是当前前端扩展结构，后端尚无独立模块表，模块详情仍保存在本地，同时随平台更新写入后端 `configJson`。

浏览器中的演示数据保存在键 `sxpt_web.training.demo.v1` 下。后台总览提供“恢复演示数据”，便于重复演示完整链路。

## 当前证据边界

本 Demo 遵循当前实验口径：平台能确认学员访问过页面并执行了预设流程动作，但不能可靠证明学员操作了业务系统中的哪一条具体数据。因此：

- 客观完成依据是页面访问、流程按钮和阶段时序；
- 页面明确提示该证据边界，避免将平台推断包装成强业务证明；
- 教师可结合过程轨迹补充主观评分；
- 后续若业务方提供业务单号回传或结果校验接口，可在不改页面主流程的前提下增强证据可信度。
